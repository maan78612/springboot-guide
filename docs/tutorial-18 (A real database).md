## 1. Why H2 and `create-drop` Must Retire

In early development, H2-in-memory with `spring.jpa.hibernate.ddl-auto=create-drop` was convenient because it started instantly without external dependencies. However, in production:
1. **Data Dies with the Process**: In-memory databases cannot persist transactions or user orders across server restarts.
2. **Unpredictable Schema Generation**: Hibernate invents table column types and constraints from Java reflections. You cannot let ORM guesswork manage production tables holding live customer data.
3. **Zero Migration History**: You cannot run `create-drop` against existing customer records without wiping the database.

### The Production Separation of Concerns
```text
┌───────────────────────┬────────────────────────────────────────────────────────┐
│ Tool                  │ Responsibility                                         │
├───────────────────────┼────────────────────────────────────────────────────────┤
│ Flyway                │ OWNS the schema: executes numbered, immutable SQL      │
│                       │ scripts in strict order and tracks applied migrations. │
├───────────────────────┼────────────────────────────────────────────────────────┤
│ Hibernate             │ AUDITS the schema: ddl-auto=validate verifies that     │
│                       │ Java entities match existing database columns.         │
├───────────────────────┼────────────────────────────────────────────────────────┤
│ PostgreSQL            │ Real production relational database engine.            │
├───────────────────────┼────────────────────────────────────────────────────────┤
│ H2                    │ Dev / fast unit tests (built by the SAME Flyway SQL).  │
└───────────────────────┴────────────────────────────────────────────────────────┘
```

```properties
# application.properties
spring.jpa.hibernate.ddl-auto=validate
```

| Key | Why we use it |
| :--- | :--- |
| `ddl-auto=validate` | Hibernate checks mappings but does not create or modify tables. Startup fails if entities and columns drift apart. |
| Flyway migrations | Versions schema alterations deterministically across dev, staging, and production environments. |

## 2. Add Flyway Migration Scripts

Flyway migration scripts are located in `src/main/resources/db/migration/` and follow the strict naming convention `V<Version>__<Description>.sql` (note the **two underscores**):

### `V1__init.sql`: The Core Schema
```sql
-- CREATE TABLE defines a database table; PRIMARY KEY identifies each row.
CREATE TABLE author (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(255) NOT NULL
);

CREATE TABLE genre (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(255) NOT NULL
);

CREATE TABLE user_account (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    email VARCHAR(255) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    role VARCHAR(50) NOT NULL
);

CREATE TABLE book (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title VARCHAR(255) NOT NULL,
    author_id BIGINT NOT NULL REFERENCES author(id),
    owner_id BIGINT REFERENCES user_account(id),
    price DECIMAL(10,2) NOT NULL,
    cost_price DECIMAL(10,2),
    deleted BOOLEAN NOT NULL DEFAULT FALSE
);

CREATE TABLE book_genre (
    book_id BIGINT NOT NULL REFERENCES book(id),
    genre_id BIGINT NOT NULL REFERENCES genre(id),
    deleted BOOLEAN NOT NULL DEFAULT FALSE,
    PRIMARY KEY (book_id, genre_id)
);

CREATE INDEX idx_book_author_id ON book(author_id);
CREATE INDEX idx_book_owner_id ON book(owner_id);
```

| SQL Key | Why we use it |
| :--- | :--- |
| `PRIMARY KEY` | Uniquely identifies each row in the table. |
| `GENERATED BY DEFAULT AS IDENTITY` | Standard SQL syntax supported by both PostgreSQL and modern H2 for auto-incrementing IDs. |
| `DECIMAL(10,2)` | Stores monetary prices with fixed precision, avoiding binary floating-point rounding errors. |
| `DEFAULT FALSE` | Pre-sets `deleted` for soft-delete compatibility without manual scripting. |

## 3. Run PostgreSQL Locally with Docker Compose

Create `compose.yaml` in the project root:

```yaml
services:
  postgres:
    image: postgres:17
    container_name: bookshop-postgres
    ports:
      - "5432:5432"
    environment:
      POSTGRES_DB: bookshop
      POSTGRES_USER: bookshop
      POSTGRES_PASSWORD: bookshop-local-pw
    volumes:
      - postgres-data:/var/lib/postgresql/data

volumes:
  postgres-data:
```

Start the container:
```bash
docker compose up -d
```

Run the application targeting PostgreSQL:
```bash
SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:5432/bookshop \
SPRING_DATASOURCE_USERNAME=bookshop \
SPRING_DATASOURCE_PASSWORD=bookshop-local-pw \
./mvnw spring-boot:run
```

## 4. The Real Bug H2 Hid: The `bytea` Type Inference Trap

When running our JPQL search query on H2:
```java
where (:search is null or lower(b.title) like lower(concat('%', :search, '%')))
```
It ran without error. But when executed against real PostgreSQL, the endpoint crashed with:
```text
ERROR: function lower(bytea) does not exist
```

**Why it happened**: When `:search` is passed as `null`, PostgreSQL's query planner cannot infer the data type of an untyped parameter, defaulting to `bytea` (raw bytes). PostgreSQL does not have a `lower(bytea)` function!
**The fix**: Explicitly cast the query parameter in JPQL:
```java
lower(concat('%', cast(:search as string), '%'))
```
This demonstrates the importance of dev/prod database parity: H2 is lenient, while PostgreSQL is strict and type-safe.

## 5. Common Migration Pitfalls

1. **Never Modify an Applied Migration Script**:
   Flyway computes a SHA-256 checksum of every migration file when applied. If you change even a single character in `V1__init.sql` after it ran, Flyway will fail application startup with a `Checksum mismatch` error. Always write a new migration file (e.g. `V3__add_isbn.sql`).
2. **Never Run `ddl-auto=update` alongside Flyway**:
   Having both tools attempt schema modifications results in conflicting states and locked tables. Always set `spring.jpa.hibernate.ddl-auto=validate`.
